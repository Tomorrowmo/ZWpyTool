# PidTest —— 持久标识存活性验证

**一句话：验证「直接编辑改变拓扑后，实体标识还能不能查回来」。**

这是"对话式改模"整个架构的地基假设。**半天跑完，结论直接决定 Demo 的工期和复杂度。**

同时对比两条技术路线：

| 路线 | 打标 | 查回 | 特点 |
|---|---|---|---|
| **A · 命名** | `ZwEntityNameSet` | `ZwEntityGetByNameAndType` | 用户可见、可读、可被人为修改 |
| **B · 唯一 ID** | `ZwEntityUniqueIdGet` | `ZwEntityGetByUniqueId` | 内核级、不透明字节块、用户看不见 |

**看哪个存活率高，语义层就用哪个。**（也可能是两个都用：A 给人看，B 做锚点。）

---

## 为什么不做成模板命令

三个命令全是**非模板命令**（`~` 前缀）：

- ❌ 不需要 `.ui`
- ❌ 不需要 `.tcmd`
- ❌ 不需要装 Qt
- ✅ 一个 `.cpp` + `.h` + `.def` 就能编译

**绕开所有界面依赖，把最大的架构风险先出清。** 预览机制（`cvxEchoStart`/`cvxEchoEnd`）和 UI 是下一步的事。

---

## 建工程步骤

### 1. 先验证向导模板本身能跑

装完 ZW3D 后：

```
双击 <ZW3D安装目录>\api\ZW3DTemplateVSIXProject.vsix
```

VS 里新建 ZW3D 项目 → **什么都不改直接生成** → 把生成的 `.dll` 和 `.zrc` 拷到 `<ZW3D安装目录>\apilibs\`（没有就建）→ 启动 ZW3D → 命令行输入 `~HelloZW3DAPI`。

**看到 "Hello ZW3D API!" 才往下走。** 看不到就对着《ZW3D API 简介》第六章 FAQ 排查，八成是这四条之一：初始化函数名没跟 DLL 同名 / `.def` 没导出 / 没调 `cvxCmdFunc` 注册 / ZRC 没和 DLL 同目录。

### 2. 换成 PidTest

- 新建 ZW3D 项目，**工程名必须叫 `PidTest`**（DLL 名 → 初始化函数名 `PidTestInit`，必须对上）
- 把本目录的 `PidTest.h` / `PidTest.cpp` / `PidTest.def` 加进工程，删掉模板自带的示例源文件
- 项目属性 → 链接器 → 输入 → **模块定义文件** 填 `PidTest.def`
- 生成 → `x64\Release\PidTest.dll`
- 拷到 `<ZW3D安装目录>\apilibs\`，重启 ZW3D

> 本工程**不需要 `.zrc`**（没有 UI 资源），后期生成事件里那条 `zrc.exe` 命令可以留着，无资源时不生成也不报错。

### 3. 跑

先建一个测试零件：**画个六面体，在上面打 3~5 个孔**（不同直径、有沉孔更好）。然后：

```
~PidMark      →  遍历所有面打标，输出统计，写 C:\Temp\pid_test.csv
~PidEdit      →  找第一个圆柱面，半径 +1（孔径 +2），制造拓扑变化
~PidCheck     →  按名字 / 按 UniqueId 分别查回，输出存活率
```

> `C:\Temp\` 目录要先建好，或者改 `PidTest.cpp` 里的 `kCsvPath`。

## 怎么读结果

`~PidCheck` 会打印：

```
PidCheck: 共 N 个面 | 按名字存活 X (x%) | 按UniqueId存活 Y (y%) | 两者都在 Z | 全丢 W
```

| 结果 | 含义 | 后续动作 |
|---|---|---|
| **两者都接近 100%** | 🟢 最好的情况。标识稳定 | 架构按"一次打标、按名索引"走，Demo 工期不变 |
| **只有 UniqueId 高** | 🟡 用 UniqueId 做锚点，名字只作展示 | 语义层多一层映射表，工期 +2~3 天 |
| **只有名字高** | 🟡 用命名方案 | 注意名字会被用户在界面上改掉，要做保护 |
| **被编辑的那个孔丢了、其他都在** | 🟢 **正常且可接受**。只有拓扑真变了的面失效 | 做"增量重新打标"即可，这是预期行为 |
| **两者都大面积丢失** | 🔴 **架构假设不成立** | 退回"每轮全量重建索引 + 几何特征匹配"，Demo 复杂度和工期要重估。**这条要第一时间知道** |

**重点看的不是总体存活率，而是：没被编辑到的面有没有丢。** 如果一次改孔径导致满模型的标识全废，那就是硬伤。

## ⚠️ 编译前要核对的三处

代码里标了 `[TODO-VERIFY]`，都是我没能从 chm 完全确认的：

1. **`ezwEntityType` 里"面"的枚举名** —— 代码假设是 `ZW_ENTITY_FACE`。
   在 chm 搜 `ezwEntityType` 看实际取值。（已知同族的有 `ZW_ENTITY_ALL` / `ZW_ENTITY_CURVE_LIST` / `ZW_ENTITY_SKETCH` / `ZW_ENTITY_SKETCH_3D`，来自官方示例 17。）
2. **`szwEntityIdentifier.innerData` 是否需要调用方释放** —— chm 里没找到配套的 Free 接口。代码按"自己深拷贝一份"处理，如果确认原始的也要释放，在 `PidMark` 里补一句。
3. **各函数的 `#include` 行** —— 代码里的头文件是按模块命名规则推定的（`ZwEntity*`→`zwapi_entity.h`、`ZwShape*`→`zwapi_shape.h`、`ZwFace*`→`zwapi_face.h`），这个规则已被实测确认多次，但编译报错的话，直接看 chm 里该函数页顶部的 `#include` 行。

**这三处都是编译期就会暴露的，不会埋雷。**

## 顺带能得到的信息

`~PidMark` 除了打标，还会顺手报告：

- 这个零件有多少个面
- 其中多少个是**圆柱面**（≈孔的候选）
- **`cvxPartInqHoles` 实际认出几个孔**

最后一条特别有价值：**它告诉你"孔识别"到底靠不靠谱**。如果你打了 5 个孔它只认出 3 个，语义层就得靠圆柱面自己补；如果 5 个全认出来还带着 `Standard`/`Screw`/`Size`/`Fit`，那语义标签基本白送。

## 跑完之后

不管结果如何，下一个实验都是：

**拿一个真实的 Creo 工装文件，`ZwFileProeImport` 导进来，再跑一遍 `~PidMark`。**

看两件事：
1. 装配层级是否完整、有没有弹窗（决定能否批量）
2. **导入的哑几何上，`cvxPartInqHoles` 还能认出孔吗**

第 2 点是整个方案最关键的未知数——**孔识别在原生建模的零件上好使，不等于在导入的哑几何上好使**。这个必须实测。
